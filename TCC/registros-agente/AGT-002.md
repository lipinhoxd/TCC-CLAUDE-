## 2. Objetivo

Criar a camada de modelo de dados e persistência da plataforma: esquema do banco, mecanismo de
migrações, acesso aos dados e testes, de acordo com `docs/especificacao/06-MODELO-DE-DADOS.md`,

---

## 3. Resultado esperado

Ao final, o projeto deve ter um banco de dados relacional criado por migrações versionadas, com as
entidades do modelo conceitual (usuário, excursão, reserva, pagamento, retenção de vaga, reembolso,
histórico/auditoria, sessão e token), restrições de integridade, uma camada de acesso aos dados
com transações, configuração por variáveis de ambiente e testes automatizados que comprovem o
esquema e as restrições.

Não deverão ser implementados cadastro, autenticação, reservas, pagamentos, regras de cancelamento,
rotas de API de negócio nem telas.

## 5. Instrução original enviada ao agente

Você está iniciando a atividade experimental AGT-002 — Modelo de dados e persistência.

CONTEXTO

Este projeto faz parte de um Trabalho de Conclusão de Curso que investiga a utilização de um agente de Inteligência Artificial Generativa como ferramenta de apoio ao desenvolvimento de software sob supervisão humana.

O projeto experimental consiste no desenvolvimento de uma plataforma web para gerenciamento de excursões. A AGT-001 já criou a fundação técnica (front-end React com Vite e TypeScript, API Node.js com node:http, ESLint, TypeScript, Vitest). Leia o arquivo CLAUDE.md, o registro TCC/registros-agente/AGT-001.md e a especificação em docs/especificacao/, em especial 03-REQUISITOS-NAO-FUNCIONAIS.md, 04-REGRAS-DE-NEGOCIO.md e 06-MODELO-DE-DADOS.md, antes de começar.

OBJETIVO DA ATIVIDADE

Criar exclusivamente a camada de modelo de dados e persistência da aplicação: esquema do banco de dados, migrações, acesso aos dados e testes, de acordo com o modelo conceitual de docs/especificacao/06-MODELO-DE-DADOS.md.

Nesta atividade, não implemente funcionalidades de negócio, como cadastro de usuários, autenticação funcional, reservas, pagamentos, cálculo de cancelamento ou reembolso, rotas de API de negócio, telas ou processos automáticos. Esses itens pertencem às atividades posteriores.

REQUISITOS DESTA ATIVIDADE

- escolha da tecnologia de banco de dados relacional;
- esquema com as entidades: usuário, excursão, reserva, pagamento, retenção de vaga, reembolso, histórico/auditoria, sessão e token;
- migrações versionadas e repetíveis;
- CPF e e-mail únicos (RN-002 e RN-003);
- valores monetários em centavos inteiros (RN-038) e instantes em UTC (RN-039);
- integridade referencial e restrições de domínio;
- estrutura que impeça ocupação acima da capacidade (RN-021, RNF-008), explicando como a concorrência será tratada na AGT-008 (RN-040);
- camada de acesso aos dados com transações (RNF-009);
- estrutura de auditoria sem senhas, tokens ou dados desnecessários (RN-041 e RN-042);
- configuração por variáveis de ambiente e atualização do .env.example;
- testes automatizados do esquema, das restrições e das transações;
- documentação mínima de uso e de recriação do banco local.

2. Não altere os requisitos ou regras de negócio definidos pelo projeto.
3. Não inclua credenciais, tokens, senhas ou outros dados sensíveis no repositório. Use somente dados fictícios.
4. Não reutilize código funcional de projetos anteriores nem consulte o repositório do estudo piloto.
5. Não altere ou remova os arquivos existentes dentro das pastas TCC e docs/especificacao, exceto para preencher os campos de execução deste registro.
6. Não modifique os registros experimentais existentes.

8. Você pode tomar decisões técnicas de baixo impacto necessárias, desde que as documente no relatório final.
9. Não realize commit Git. O commit será realizado somente após revisão humana.
